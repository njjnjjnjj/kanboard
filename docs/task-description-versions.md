# 任务说明历史版本与 SOP 更新

## 本次行为

- 任务说明保存整理后的完整 Markdown 正文。仅 Agent 通过 MCP 修订时生成修改记录，包含修改前后正文、修改摘要和保存时间；人工编辑及相同正文重试不生成记录。
- 升级时保留任务当前正文，旧的人工编辑和迁移基线记录不再展示；现有 Agent 记录会补齐当次修改前的正文，不推测未留存的历史。
- 状态备注、阻塞详情及操作备注独立保存，由 MCP 历史查询接口返回独立的 notes，不再追加到任务说明。
- 原有自定义 SOP 配置保留。任务派发提示词、SOP 查看器及 MCP 输出补充任务说明修订规则；默认 SOP 和项目内插件技能同步更新。

## 人工验收

启动包含本次 Rust 和前端代码的新版本，首次启动会执行数据库迁移。重新连接 MCP 后检查新工具是否可用。

| 验证项 | 操作 | 预期结果 |
| :--- | :--- | :--- |
| 图标入口 | 查看任务说明标签行 | 最右侧显示历史图标，悬停提示「Agent 修改记录」 |
| 人工修订 | 人工编辑说明并保存，重新打开修改记录 | 正文正常保存，不要求摘要，不生成历史记录 |
| Agent 修订 | 通过 MCP 提交完整说明、摘要和原文，点击左侧对应记录 | 右侧直接显示该次修改前后的增删行，无新旧版本选择器 |
| 记录预览 | 点击「修改后正文」，切换左侧记录 | 以只读 Markdown 展示该次修改后的正文，不改动当前草稿 |
| 文档超链接 | 在说明或历史正文中点击 `[方案](/D:/项目/docs/方案.md)` | 本机 Markdown 或 TXT 文档在独立只读窗口打开；链接中的文件需实际存在 |
| 并发保护 | 两处读取同一原文，一处先修改，另一处再提交不同正文 | 后一次保存被拒绝，提示对比最新版本，原有新版本不被覆盖 |
| 无重复版本 | 不改正文重复保存，或仅改标题、状态 | 不增加说明版本 |
| 备注隔离 | 添加操作备注、状态说明或设置阻塞 | 仅增加独立操作记录，任务说明正文及其版本数保持不变 |
| SOP 输出 | 查看设置中的 SOP，复制或拖出任务提示词 | 包含整篇修订、修改摘要、原文校验和历史查询规则，原自定义规则保留 |

## Agent 调用约定

先读取 `get_task(task_id)`，保留返回的 `task.description`，再调用：

```json
{
  "task_id": "任务 ID",
  "description": "整理后的完整 Markdown 正文",
  "change_summary": "简要描述本次修改",
  "expected_description": "读取时的任务说明原文"
}
```

工具名为 `update_task_description`。`change_summary` 不得为空；正文允许清空。冲突后先重新读取并比较，不得自动覆盖。通过 `list_task_description_versions(task_id)` 查询历史和独立操作记录。

`append_task_notes` 保留为独立操作备注接口，不再修改正文。旧版运行程序仍会沿用旧接口行为，验收前须启动本次代码对应的新版本。
