# 任务状态聚焦功能评估

评估日期：2026-10-28。对应任务：`bd0d3701-916b-4d01-8f27-8fffdd3dfbae`。

用户已确认采用列独立折叠方案，需求和验收条件已同步至看板任务。本文保留评估依据，并补充实现与验证结果。

## 结论

有实用价值，建议优先增加**可独立展开、收起的看板列**，在看板现场操作，并提供“展开全部”。它可以采用类似横向手风琴的视觉表现，但允许同时展开多列，便于同时关注“进行中”“待验证”和“阻塞”。

本轮不建议同时引入状态筛选、保存视图和全局设置。先验证列折叠能否满足临时聚焦；如果实际需要完全隐藏其他状态，再考虑看板工具栏内的状态多选筛选。

这是基于当前源码、公开看板原则和用户所述场景作出的产品判断，不是用户使用频率或效率提升的实测结论。

## 是否符合看板原则

《The Kanban Guide》强调定义和可视化工作流、管理工作流中的任务以及控制 WIP，并未指定某一种软件控件。[2025 版指南](https://prokanban.org/the-kanban-guide)

据此推断，状态聚焦可以作为完整看板上的辅助视图；是否合理取决于是否仍能了解流程和发现积压，而非是否使用筛选按钮。只显示部分任务本身，也不足以证明整个应用符合全部看板实践。

已有产品采用这两种交互：Jira 官方文档说明可对 Scrum 或 Kanban 看板使用快捷筛选；Kanban Tool 官方文档说明可通过列头折叠和重新展开列。[Jira 筛选说明](https://support.atlassian.com/jira-software-cloud/docs/configure-quick-filters/)、[Kanban Tool 列折叠说明](https://kanbantool.com/support/kanban-board/how-to-collapse-a-column-or-a-swimlane-on-my-kanbanboard)

本项目更适合先折叠列，是因为收起后仍可保留状态、数量和超限提示。该建议不是指南规定，也不意味着永久隐藏列就必然违反看板原则。

## 方案比较

| 方案 | 收益 | 成本与不足 | 建议 |
| --- | --- | --- | --- |
| 列独立折叠，保留窄摘要 | 释放宽度，仍能看见流程和积压，可同时展开多列 | 需要处理摘要、网格、泳道和拖拽边界 | 首选 |
| 看板工具栏提供状态多选 | 可以精确只显示某几种状态，能与现有筛选组合 | 完全隐藏列后容易漏看阻塞；需要显式筛选提示和恢复入口 | 确有完全隐藏需求后再增加 |
| 全局设置勾选显示状态 | 可以保存长期个人偏好 | 临时切换路径长，离开设置后不易看出有列被隐藏 | 不作为主要入口 |
| 每次只展开一列的互斥手风琴 | 操作规则简单 | 无法同时对照进行中、待验证、阻塞，削弱流程比较 | 不采用 |

如果选择状态筛选，选中的状态之间应为“或”，与项目、标签、搜索及现有快捷筛选之间为“且”。不能仅替换当前快捷筛选，否则会失去“某状态中的高优先级任务”等组合能力。该规则属于备选方案，不纳入首版折叠范围。

## 已确认的首版边界

1. 无已保存偏好时，默认仅收起“已完成”，其他列展开；有偏好时恢复用户的手动选择。每列提供明确的展开／收起按钮；按钮支持键盘操作，并暴露 `aria-expanded` 状态。
2. 收起后保留窄列摘要，显示列名、原有范围内的任务总数、WIP 限额及超限提示；卡片区域收起，释放宽度给展开列。搜索结果不应冒充完整 WIP 数量。
3. 允许多列同时展开，也允许全部收起；全部收起仍能看到 7 个摘要，工具栏提供“展开全部”，避免无出口。
4. 普通看板、泳道和项目／标签共享本机列折叠偏好；泳道中同一状态列同步收起，保持横向对齐。手动切换或“展开全部”通过 `localStorage` 记忆，重启后恢复；不增加项目专属配置。临时拖拽、通知定位及快速添加任务引发的展开不覆盖手动偏好。
5. 折叠、展开和恢复全部只改变界面，不改任务状态、排序、状态历史、WIP 限额或统计数据，也不修改 MCP 查询结果。
6. 拖动本看板任务进入收起列区域时，目标列自动展开，随后可继续拖入排序、跨列流转；快速松手时以实际目标列为准，放至该列末尾。手动折叠和“展开全部”在拖拽中仍不可用，回收站命中优先于展开。拖拽成功、取消或保存失败后，临时展开列恢复收起；原本手动保持展开的列不受影响。泳道继续遵循原有项目拖拽分组。
7. 搜索和现有筛选仍筛选卡片，不自动改变列折叠状态。若匹配结果位于收起列，在摘要显示匹配数量并允许展开，避免将收起误认为没有结果。
8. 通过通知或其他定位入口打开任务时，自动展开其所属列，再沿用现有的范围和筛选调整逻辑；避免详情已打开而卡片仍藏在收起列内。
9. 折叠沿用应用统一的短促过渡：列宽为 180 ms，标题及卡片显隐为 120 ms；键盘和系统减少动态效果模式即时响应。不增加预设视图、自动折叠空列、状态模型或数据库迁移。

首版采用上述列独立折叠方案，不增加完全隐藏状态的多选筛选。

| 验收点 | 操作与预期 |
| --- | --- |

| 流转与数据完整性 | 拖入收起列时自动展开，快速松手不会落到此前经过的列；保留原有任务和项目分组，取消拖动不流转，回收站优先；不因仅展开产生数据库写入 |
| 定位与恢复 | 从通知打开收起列的任务，所属列自动展开但不覆盖偏好；重启后恢复手动选择，尚无偏好时默认仅收起已完成 |
| 键盘与窄窗口 | 通过键盘切换列状态并恢复全部；窄窗口中摘要可读，展开区可访问，无卡片被静默裁掉 |

### 验收反馈：拖入收起列时自动展开

按用户反馈，收起列现支持拖入时自动展开。复用现有指针跟踪，鼠标移动、触摸移动、原生 `dragenter` 和 `dragover` 共用命中判断；回收站优先，不对普通鼠标移动或外部拖入自动展开。

实际浏览器拖拽还发现并修正了快速松手的落点问题：新展开的 Sortable 列可能尚未接收到 `dragover`，此前会把任务留在上一个经过的列。现在记录本次自动展开列的真实松手目标，必要时将任务放至目标列末尾，再沿用原有保存流程；普通排序仍使用 Sortable 确定的位置，泳道继续限制同项目流转。取消拖动恢复原任务状态和顺序；自动展开列的最终状态按下一节的最新规则恢复。

### 动画与闪动优化（2026-10-29）

折叠时原先的网格轨道类型从固定宽度直接切换到弹性宽度，且列表立即卸载，容易造成整体跳变。现统一轨道为可插值的 `minmax()`，以 180 ms 横向手风琴过渡；标题和任务列表在退出时保留 120 ms 用于淡出，退出内容立即设为不可交互并从辅助技术中隐藏。快速反向切换时移除退出属性，标题 ID 按状态区分，避免残留或重复。

全局交互时长统一为 `--motion-fast: 120ms`、`--motion-standard: 180ms`、`--motion-panel: 220ms`，复用 `--ease-out` 缓出曲线，覆盖按钮、标签菜单、表单反馈、抽屉、设置开关、提示和 Sortable 排序。移除 `transition: all` 及 Agent 卡片的循环脉冲、转圈，保留静态活动标记与有实际计时意义的撤销倒计时。

- 键盘操作使用 0 ms 交互过渡；指针按下后恢复常规节奏。系统减少动态效果设置同时控制 CSS 和 Sortable，支持运行中切换并在卸载时清理监听。
- 本轮全量 30 个测试文件、183 项测试通过，TypeScript 和差异格式检查通过。
- 实际页面采样记录到列宽由 180 px 至 64 px 的 11 个宽度状态，看板透明度始终为 1；这用于确认存在连续过渡，不是帧率或设备性能保证。
- 实际页面核对了快速展开／收起／展开后的最终状态、每列只保留一个标题且无退出图层残留；键盘触发的网格过渡时长为 0 s，鼠标触发为 0.18 s；泳道同状态列位置与宽度一致；动画期间快速拖入仍可正确流转并自动收起。
- 页面和截图使用隔离测试数据及模拟 Tauri IPC；未运行新桌面构建或验证原生 WebView 的实机动画观感。临时验证入口、浏览器页面和服务在检查后清理，未创建 Git 提交。
