## 已确定的产品事实

沿用前期已明确的产品定位：Kanboard 是桌面任务工作台。用户主要在查看当前任务、拖拽流转、聚焦状态和打开详情之间切换。

- 信息优先级：当前操作的任务与落点，其次是进行中／阻塞／待验证状态，然后是其他任务、详情与配置。
- 高频操作：选择、搜索、键盘导航和拖拽反馈，应当即时响应。
- 常规操作：列折叠、详情开关、菜单和选择器，动画只帮助理解状态和空间关系。
- 偶发操作：项目编辑、设置、统计和文档全屏，应有明确层级，但不能遮断工作连续性。
- 产品性格：紧凑、安静、干练、可预测；保持现有信息架构、配色和业务布局。

## 三种交互方向

候选方向保持业务布局；差异放在交互组织、视觉主次、面板生命周期和详情行为，不以更换颜色或时长冒充设计差异。

### 连续工作台（已选定）

- **产品模型**：任务、列和详情是持续存在的工作对象，状态变化沿用它们的空间关系。
- **布局结构**：保留主看板、状态摘要和右侧详情；在必要的布局变化后用视觉补间接续位置，避免让整个任务集合逐帧重排。
- **主导区域／视觉锚点**：看板主导，当前任务与目标列提供连续锚点。
- **交互轴**：并行操作；用户可以在运动途中反向切换，新操作从当前呈现状态接续。
- **面板与详情行为**：内容与焦点尽量保留，详情作为侧层承接当前任务；菜单从触发点进入，关闭后回到触发处。
- **密度**：高；保持任务信息可读，不用大幅位移或装饰性留白换取轻松感。
- **产品优势**：适合反复折叠、多列对照、跨列拖拽和边看边编辑，最接近现有工作习惯。
- **代价**：需要协调位置测量、视觉补间、退出和中断；必须处理文字清晰度、滚动、后台刷新和拖拽命中。

### 定帧控制台

- **产品模型**：操作立即改变工作状态，动画只确认结果。
- **布局结构**：保持原有分区；布局和列宽一次到位，随后只对当前结果做局部、低幅度显隐反馈。
- **主导区域／视觉锚点**：静态看板主导，焦点、选中和落点标记承担定位，不追踪完整运动路径。
- **交互轴**：即时命令与结果；没有排队的空间移动，也不等待退出后再执行操作。
- **面板与详情行为**：仅保留当前必要内容；详情在固定位置出现或消失，浮层使用最小显隐而非滑行。
- **密度**：很高；面向高频操作和较多任务，尽量避免内容在阅读期间移动。
- **产品优势**：节奏最克制，对低性能设备和键盘使用友好，补间及中断成本较低。
- **代价**：空间变化解释较弱，列宽仍是瞬时变化；如果用户期待明显连续的展开收拢，这个方向可能偏硬。

### 聚焦工作舱

- **产品模型**：当前操作对象是一个短时工作舱，背景保持稳定，变化集中在目标区域。
- **布局结构**：保留看板和详情位置，动画按“当前目标、临时层、背景”分层组织；背景不跟随所有局部动作一起过渡。
- **主导区域／视觉锚点**：当前任务或目标列优先，看板其他区域作为稳定参照。
- **交互轴**：局部交接；先让操作目标和反馈明确，再由详情或菜单承接，真实状态和输入仍立即生效。
- **面板与详情行为**：当前操作的临时层按阶段复用、退出；详情强调从选中任务到固定侧层的交接，背景保留原状态。
- **密度**：主看板仍高，当前工作舱中等；通过交互主次分配注意力，而非增加卡片或修改页面框架。
- **产品优势**：适合打开详情后持续编辑、处理阻塞与验收，辅助面板不会与主看板争夺注意力。
- **代价**：视觉编排更明显，容易把频繁并行操作做得拖沓；对连续拖拽和快速切换的约束更高。

## 当前建议与范围约束

建议选择“连续工作台”，因为现有需求的核心是持续操作、空间连续和拖拽正确性。它需要改变运动与布局之间的组织方式，而非继续套用全局时长。

| 导航与布局 | 沿用项目／标签范围、状态列、泳道及右侧详情的位置，不重做业务信息架构 |
| 密度 | 任务区域紧凑，表单保留现有阅读间距，浮层保留必要分隔；不机械统一所有间距 |
| 表面与圆角 | 沿用状态列、真实任务卡、抽屉和对话框的语义边界，不新增装饰容器 |
| 色彩与字体 | 保留现有字体和行动／选择／状态／警告／项目身份配色；不靠渐变、字体替换或更强颜色制造差异 |
| 高频反馈 | 选择、搜索、键盘导航、按下状态即时响应；动画不得延迟真实命令 |
| 布局变化 | 一次读取旧位置、一次更新最终布局、一次读取新位置，然后用合成动画连接；不逐帧改变网格宽度让正文反复换行 |
| 文字与层次 | 正文不按宽度缩放；必要的旧内容只作为不可交互的退出表示，动画完成或中断后清理；实际对象、焦点和数据仅有一份 |
| 拖拽 | 开始拖拽前清理布局补间；手势进行中布局与命中立即生效，Sortable 只负责自身排序反馈；结束后恢复收起可作视觉接续 |
| 浮层 | 菜单、日期和选择器使用相同生命周期与触发处起点；对话框小幅进入，详情从右侧承接；进入慢于退出，无回弹 |
| 打断 | 新操作读取当前呈现状态并接续；不排队、不等待旧动画，不保留透明拦截层。滚动、调整窗口或切换范围时让位给真实操作 |
| 键盘与减少动态效果 | 仅决定当前操作是否补间，不全局把正在进行的过渡时长改成 0；系统减少动态效果启用时立即完成空间动画 |
| 基础节奏 | 布局约 200 ms；详情进入／退出约 200／160 ms，对话框约 180／140 ms，浮层约 140／100 ms；按实际位移收敛，不做机械同步 |
| 技术边界 | 优先原生 Web Animations API 与 Vue 过渡钩子；动画不支持时直接完成状态变化，不依赖新增动画库 |
| 明确禁用 | 逐帧网格伸缩、正文缩放、全看板淡出、全局输入方式截断动画、持续发光／回弹，以及以时长或静态截图代替体验验收 |

视觉检查采用 `gpt-taste` 中层级与对比可读性的适用部分；其展示页随机布局、营销结构和大幅滚动效果与本任务保留业务布局的约束不符。交互抛光采用 `emil-design-eng`，在实现后另做 KEEP／CHANGE／REMOVE 审查。

## 实现与交互抛光

列的逻辑布局一次提交，原生 Web Animations API 只连接呈现位置。表头与 Sortable 列表保持挂载，收起列表使用隐藏、禁用和 inert；不以反复创建组件模拟折叠。正文保持实际字形，只有改变展开形态的目标列需要短暂的旧内容表示；相邻列只移动位置。旧表示仅复制视口内卡片，没有任务标识、焦点或交互能力。

布局样式直接设置到网格和泳道行，避免把变化的布局变量继承给整棵任务树。屏外普通卡片用浏览器的内容可见性优化，首次未绘制时估算内容高度为 120 px，绘制后由浏览器记忆实际高度。Agent 标记、聚焦和拖拽卡片保持完整绘制。该优化保留真实节点和 Sortable 顺序，不引入另一份任务数据。

准备补间的实测开销超过 8 ms 后，200 ms 内的后续连续操作直接落位并清理视觉层；短暂停顿后恢复补间。此预算为绘制留出时间，不保证任意任务量均达到 60 fps，也不延后业务命令。

详情、设置、项目、统计、历史和全屏面板，以及标签、选择器、日期和提示，统一进入／退出生命周期。全屏层仅淡入淡出；其他浮层使用小幅平移，不缩放正文。进入／退出可接续当前呈现状态，退出内容立即 inert。键盘策略按当前动作读取，打字不会截断此前的动画；提示消息不接管焦点。

| Before | After | Why |

| 网格轨道逐帧变宽，表头与列表独立卸载、淡出 | 一次完成布局，保留组件，局部位置补间 | 减少反复换行、重排及多个退出层造成的闪动 |

## 独立 KEEP／CHANGE／REMOVE 审查

本节在实现和交互抛光后单独核对，保留既定页面结构。

- **KEEP**：状态列、任务卡、WIP 和 Agent 标记承担看板业务语义；保留现有色彩、密度、分隔和详情位置。倒计时仍表示真实撤销窗口；启动条只表示真实等待，不添加装饰循环。
- **CHANGE**：动画只解释状态或位置变化；统一浮层中断、退出与焦点规则，对高负载连续操作采用即时反馈。减少动态效果、键盘和原生拖拽优先于补间。保持任务数据与交互节点唯一。
- **REMOVE**：逐帧网格宽度过渡、表头／列表重复退出、全局键盘时长归零、普通按钮／行的缩放，以及宽度和 all 的笼统过渡。未引入新卡片布局、营销区、渐变装饰、假统计或新动画依赖。Agent 彩虹框属于执行状态，保留它的语义。

## 实际验证与边界

- 前端全量测试：32 个文件、196 项通过。随后设置 Esc 与显式 autofocus 优先级调整的 25 项针对性测试通过。TypeScript 无输出类型检查通过；未构建 Java、Rust 或桌面发布包。
- 原生浏览器拖拽：真实 App 组件配合隔离 SQL 数据，从收集箱拖入已折叠的进行中列，落点为 doing，结束后恢复收起，35 项任务全部保留。折叠偏好、快速松手、保存失败和泳道隔离另有自动回归覆盖。
- 长列表：700 项任务，每列 100 项；进行中列表滚动到 1440 px 后折叠再展开，滚动位置仍为 1440 px，100 项节点保留，可见区域无空白占位。
- 浮层：实际打开详情、状态选择器、日期、历史、设置和项目编辑；日期 Esc 后日历消失、详情保留、焦点返回日期按钮。统计 Esc 与背景详情保留由自动测试核对。
- Agent 回归：浏览器中同时放置两张进行中的 Agent 卡片，先复现未选中无边框，再确认修复后两张未选中卡片均显示彩虹框。不是通过强制选中显示。

### 浏览器帧时间采样

使用本机内置浏览器、Vite 开发模式、1280 × 720 视口和真实 App 组件，数据库为隔离数据。每 45 ms 反向切换一次进行中列，共 10 次，requestAnimationFrame 采样 1.5 s，同时记录 Long Tasks；采样期间不读取整页辅助树。

| 场景 | 帧间隔 P95 | 最大帧间隔 | Long Tasks | 结束状态 |
| --- | --- | --- | --- | --- |
| 35 项任务 | 16.8 ms | 16.8 ms | 0 | 35 项任务、7 列，视觉层和动画均为 0 |
| 700 项任务 | 49.9 ms | 66.8 ms | 1 项，约 52 ms | 700 项任务、7 列，视觉层和动画均为 0 |

这是当前开发环境的短时压力样本，不是桌面 WebView 或低性能设备的帧率认证。700 项任务持续反向操作仍有渲染开销，不能宣称稳定 60 fps；本次已提供屏外绘制与动画预算降级，未扩大为列表虚拟化改造。系统减少动态效果和动态切换由自动测试覆盖，未修改用户系统设置。1040 px 最小窗口、其他屏幕缩放及实际桌面观感仍需用户验收；静态截图只用于核对页面状态，不代表流畅度结论。
