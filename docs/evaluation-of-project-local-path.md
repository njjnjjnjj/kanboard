# 项目本地路径功能价值评估

## 结论与建议

`project.path` 有实际用途，适合作为**可选的项目工作目录提示**保留。它目前的直接价值是把“任务属于哪个项目”补充为“这个项目在当前机器的哪里”，供接收任务的 Agent 定位。

对于已经在正确仓库中工作的会话，这条信息的增益较小；对于从全局看板接单、工作目录尚不明确的会话，它可以减少查找和重复询问。当前实现不会自动切换工作目录，也不会自动打开编辑器。

建议先保留现有可选字段及 Prompt、MCP 链路，按实际需要配置。现有证据不足以支持删除，也不足以支持立即投入一整套目录选择、IDE 启动和跨设备映射功能。是否增强应由具体使用需求决定。

本次以 2026-10-27 工作区源码和 Kanboard MCP 返回数据为依据。结论针对当前实现，不代表未来架构必须如此。

| --- | --- | --- |

## 在哪些场景有意义

| 使用场景 | 实际价值 | 边界与替代方式 |
| --- | --- | --- |
| 在正确仓库中持续开发 | 较低，可用于核对任务和仓库是否对应 | 宿主工作区、仓库信息已经能提供定位依据 |
| 从全局看板向不同项目派发任务 | 较高，Agent 可以直接取得候选工作目录 | 仍需核实目录、仓库和权限；任务说明中明确路径也能替代 |
| 当前会话位于另一个仓库 | 有帮助，可暴露任务与当前目录不一致 | 路径文本不会切换宿主工作区或扩大文件权限 |
| 项目使用独立 worktree 或多个仓库 | 单一项目路径只能提供部分信息 | 具体任务应说明实际 checkout 或相关仓库，不能自动覆盖为项目根目录 |
| 规划、调研等无需代码目录的项目 | 可以不配置 | 空值应是有效状态，不应因此阻断任务 |
| 在另一台机器或远程执行任务 | 原有绝对路径可能无效 | 需要对应主机的目录信息；当前字段没有主机绑定或目录映射 |

路径的价值取决于它能否减少真实的定位成本。它是可复用的结构化信息，不是自动化执行的唯一前提；显式任务路径、宿主上下文和外部项目映射也能承担定位作用。

配置路径与宿主目录不一致时，应核对任务目标和仓库身份，不能无条件信任任意一方。项目路径也不构成切换工作区、访问其他目录或修改其他仓库的授权。

## 保留、收起或移除的取舍

| 选择 | 收益 | 成本与适用条件 |
| --- | --- | --- |
| 保留为可选信息，维持现状（建议） | 继续支持已配置项目，保留 Prompt 与 MCP 的定位信息 | 需要维护少量已有链路；允许不用，不强制所有项目填写 |
| 保留能力，但降低设置项显著性 | 对普通任务管理用户减少认知负担 | 仅在用户明确认为界面受干扰时再考虑，当前没有可用性测试证明必须调整 |
| 移除该字段 | 减少一个设置项和相关读写代码 | 需同步处理数据、类型、Prompt、MCP、技能和测试；已配置项目需要替代定位办法 |

删除不会“不可逆地失去跨项目能力”，但会取消现有结构化定位入口，需要另行传递目录。保留也不必以增加一系列桌面功能为前提。

当前没有足够的工作量拆分和实测数据，不能承诺“半天至一天完成全部增强”“消除 70% 以上空置率”或固定的投入收益。

## 后续动作建议

本次建议先停留在保留可选字段，不实施功能扩展。可按真实需求逐项决定：

- 如果经常在项目设置中手工复制目录，再考虑目录选择器。
- 如果确实需要从看板打开工程，再单独评估“打开文件夹”或特定编辑器入口；无需一次覆盖所有 IDE 和终端。
- 如果发生路径失效导致的派工问题，再考虑存在性提示。路径处理需区分盘符根目录、UNC 路径和具体执行主机，避免简单删斜杠或统一替换造成语义变化。
- 如果开始共享数据库或远程派工，再评估按主机绑定路径；当前没有证据要求预先引入映射系统。

需要用户决定的产品方向是：是否希望 Kanboard 提供直接打开本地工程的快捷操作。该决定影响后续投入，不影响本次“保留为可选定位信息”的评估交付。

## 如何核对本次结论

阅读前两节即可核对核心判断，场景与取舍表用于决定是否值得继续投入。可以对照源码确认路径只被保存和传递，没有自动切换工作区的行为；查看文档预览解析函数，确认其基准来自当前文档而非项目字段。

可复核的现有自动化检查：

```powershell
npm test -- src/components/ProjectEditor.test.ts src/drag/agentPrompt.test.ts src/services/documentPreviewService.test.ts
cargo test --manifest-path src-tauri/Cargo.toml --lib document_preview::tests --offline
```

这些检查覆盖项目路径编辑、任务提示词和文档链接相关的既有行为，不证明采用率或未来改造收益。本任务仅修订评估文档及看板记录，未实现目录选择、打开工程、路径校验或跨主机映射，也未进行桌面实机操作验证。
